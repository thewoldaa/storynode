## Decisions

**Glob the sources in CMake rather than listing them.** With one worktree per
task, an explicit source list is a file every task must edit, so every task
conflicts with every other task. `CONFIGURE_DEPENDS` costs a directory scan on
rebuild and removes a shared surface. See `docs/ARCHITECTURE.md`.

**The core does not include a Windows header.** The document model, undo and
exporters build and run in a test process with no window and no message loop.
This is what makes wave 1's four tasks genuinely independent rather than four
tasks that all need the same window plumbing.

**The territory check runs before the worktree is created.** A conflict found
then costs nothing; the same conflict found after a day of parallel work costs
the day. This is the one check the harness performs that git cannot.

**Two implementations of the forbidden-file check, one authoritative.** The
shell version is the rule; the PowerShell version calls it rather than
reimplementing it, and the pre-commit hook shells out to it. Two independent
implementations would eventually disagree, and a commit that passes locally
and fails in CI is worse than either failing.

**The build workflow is not in the scaffold.** It was, briefly, and it failed
on every push for the only reason it could fail: `CMakeLists.txt`,
`CMakePresets.json` and `tests/CMakeLists.txt` do not exist yet, because they
are wave 0 deliverables. A permanently red `main` trains people to ignore CI,
so the workflow was removed and will return in the pull request that adds the
build system it configures.

## Bugs found by running the harness, not by reading it

Three defects that review had not caught. All are fixed, and all are worth
recording because each one would have been found the expensive way.

1. **`build/` matched at any depth.** `src/app/build/thing.cpp` — a
   reasonable directory name inside a source tree — was rejected as build
   output. The patterns are now anchored to the repository root, where the
   directories this rule exists to catch actually live.

2. **PowerShell `-like '*/**'` classified every glob as recursive.** In
   PowerShell `*` is a wildcard, so that pattern matches almost any path
   containing a slash. `src/a/*` was treated as covering `src/a/b/c.hpp`,
   which would have rejected two genuinely independent tasks as conflicting.
   Replaced with an ordinal suffix test. The Bash implementation was correct
   throughout; both now agree across seventeen cases.

3. **The task-worktree lookup never matched.** It searched for a slug of
   `wave-<task>` when the real slug is `<wave>-<task>`, so `wave-sync`,
   `wave-done` and `wave-clean` all reported "no worktree found" for a
   worktree that plainly existed. Found the first time `wave-done` was run
   against a real worktree.

A fourth issue was a bad test rather than a bad program: an early hook check
reported success when the commit had actually failed for an unrelated reason
(no git identity configured). It was re-run properly. A test that passes for
the wrong reason is worse than no test, because it is counted.

## Verified

- Territory overlap: 11 cases in Bash, 17 in PowerShell, both shells agreeing.
- Territory enforcement in `wave-done`: a file outside the declared territory
  is rejected, a file inside it is accepted.
- The full `wave-new` → `wave-done` → `wave-clean` cycle against a real
  worktree: worktree created, branch pushed, pull request opened with a body
  generated from the task declaration, and the merged-branch guard in
  `wave-clean` correctly refusing to delete an unmerged branch.
- The forbidden-file check: 15 cases in PowerShell, plus the hook catching a
  `git add -f` that bypassed `.gitignore`.
