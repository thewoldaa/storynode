## Decisions

**The model does not include a Windows header.** This is what makes the four
tasks in wave 1 genuinely independent rather than four tasks that all need the
same window plumbing, and it is what lets the model tests run on a Linux
runner.

**Sources are globbed in CMake.** An explicit source list would be a file
every task must edit, and every task editing the same file is the conflict the
harness exists to prevent.

**Messages carry intent, not state.** The page never patches its own copy
optimistically; the host applies the intent and broadcasts a fresh snapshot.
A diff protocol would be smaller and much harder to get right, and the
document is small enough that it does not matter.

**Unknown keys survive a round trip, at every level of the document.** Without
this, opening a file written by a newer build and saving it silently deletes
whatever that build added — the worst possible failure, because it destroys
data without telling anyone.

**A file declaring a newer format version is refused, not opened.** Reading it
and saving would rewrite the parts this version understands in the old shape,
producing a file that neither version handles correctly.

**Node behaviour is data, not code.** A node declares its ports and its
property values; the editor renders it from that declaration. Adding a node
type is adding a declaration, not a class.

## What testing found

Six defects, all found by running rather than by reading. They are worth
recording because each would have been found the expensive way.

1. **`ParseResult` held a `Value` before `Value` was complete.** A member of
   an incomplete type is an error rather than something a forward declaration
   can work around.

2. **Two JSON escape tests tested nothing.** MSVC translates `\uXXXX` inside a
   raw string literal as a universal-character-name before the parser sees
   the text, so `R"("A")"` reached the parser as the letter A. The tests
   passed while checking nothing, which is worse than failing. Rewritten with
   escaped literals, and the reason is now a comment in the test file.

3. **Syntax errors did not carry their position into the message.** The
   `Location` was stored but the message shown to the user said only "not
   valid JSON", which is useless in a file of several hundred lines.

4. **The same condition had two different error codes** depending on whether
   the reader or the validator caught it. A caller keying on a code had to
   know which layer got there first.

5. **Validation sent only structural problems to the page.** Graph warnings —
   dead ends, unreachable nodes — never reached the interface, so a user would
   have seen "no problems" on a story that cannot be played.

6. **A rejected document replacement still overwrote the document.** A
   document with a newer format version wiped the open story and replaced it
   with the empty shell the reader produced. Losing work is far worse than
   refusing an edit.

## Two things that looked like bugs and were not

**The status bar appeared to be missing.** A screenshot showed the window cut
off below the toolbar, and a colour scan found no footer band. The layout was
correct: the screenshot was wrong. `PrintWindow` clips DWM-composed content,
which is what a WebView2 control is, and `CopyFromScreen` captured whatever
window happened to be in front. The colour scan that "confirmed" the missing
footer was reading an empty column of graph background, where no colour change
is expected.

The resolution was to stop trusting the screenshot and ask the page to measure
itself. That measurement is now a CTest test, and it reports the footer at
`top=558 bottom=583` of a 583-pixel viewport, with the toolbar and graph not
overlapping.

**A three-size layout test tested one size.** `--verify` forced its own window
size, so three runs reported identical geometry. The option to set the size
did not exist yet. It does now, and the sizes genuinely differ: 1010x583,
706x423, 546x343, 1522x807.

## Verified

- 136 unit tests across the JSON tree, the model, the format and the bridge.
- Six CTest tests, four of which launch the built editor and check its layout
  at different window sizes.
- The layout check fails when the layout is broken: with the footer row

  `footer: bottom=5037`).

  produced `dialog-1` and `branch-1` nodes through the toolbar buttons, and
  they arrived in the document.
- The forbidden-file checker refuses a `git add -f` that bypasses
  `.gitignore`.
