- The worktree harness, in both shells: `wave-new`, `wave-list`, `wave-sync`,

- Roadmap, architecture notes, and `docs/UI-ENGINE.md` recording why the

## Decisions

**Glob the sources in CMake rather than listing them.** With one worktree per
task, an explicit source list is a file every task must edit, so every task
conflicts with every other task. `CONFIGURE_DEPENDS` costs a directory scan on
rebuild and removes a shared surface. See `docs/ARCHITECTURE.md`.

**The core does not include a Windows header.** The document model, undo and
exporters build and run in a test process with no window and no message loop.
This is what makes wave 1's four tasks genuinely independent rather than four
tasks that all need the same window plumbing.

**The territory check runs before the worktree is created.** A conflict found
then costs nothing; the same conflict found after a day of parallel work costs
the day. This is the one check the harness performs that git cannot.

**Two implementations of the forbidden-file check, one authoritative.** The
shell version is the rule; the PowerShell version calls it rather than
reimplementing it, and the pre-commit hook shells out to it. Two independent
implementations would eventually disagree, and a commit that passes locally
and fails in CI is worse than either failing.
